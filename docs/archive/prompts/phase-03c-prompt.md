WHY THIS PHASE EXISTS
Phase 3B ended with these measured limits: (a) a box that differs from the calibration by +15 percent gives false tamper verdicts in 19 percent of clean/physical runs; (b) the twin and the simulator use the same family of equations; (c) the worst-case bound was invalid on 45 of 367 bounds on a box 15 percent below the calibration, and it is very loose (about 18 times) where cooling really worked; (d) the CUSUM settings k and h were chosen from a sweep in which every setting had zero false alarms, so the choice rests on delay alone. This phase closes what CAN be closed and measures the rest. Two limits are NOT fixable in software and must stay documented as such: a slow drift that stays inside the "cooling partly working" envelope, and a mimic liar. Do not attempt to "fix" those; do not tune anything to hide them.

STEP 3: STRUCTURALLY DIFFERENT BOX MODEL (addresses "shared equations")
 a. Add a second box physics to the simulator engine, selectable by a new config key box_model: "single_node" (default, unchanged behaviour; the nine golden recordings must stay byte-identical) or "two_node": an air node and a payload node. Equations: C_a dT_a/dt = (T_amb - T_a)/R_wall + (T_p - T_a)/R_ap + Q ; C_p dT_p/dt = (T_a - T_p)/R_ap. The SENSOR measures the air node T_a (reported temperature is air temperature plus noise). The payload node is what the potency physically depends on, so for two_node boxes the TRUE temperature used for ground-truth potency is T_p; state this clearly and keep both series in the ground-truth file (a new field true_payload_temp_c; true_temp_c stays the air node for compatibility).
 b. Parameterisation (all placeholders, labelled, in config): two_node_payload_fraction (share of the total heat capacity in the payload, e.g. 0.5), two_node_coupling_tau_h (time constant of air-payload equalisation, e.g. 1.5), and the wall resistance and total capacity chosen so that the overall slow time constant is close to box_tau_h. Discretise exactly per substep with a 2x2 matrix exponential computed with numpy (eigen-decomposition or Pade; no scipy). Unit tests: steady state equals the analytic value; energy/limit checks (no cooling: both nodes converge to ambient); reduces to the single-node model when the payload fraction is 0; determinism; RNG discipline unchanged (same number of noise draws per sample).
 c. Evaluation (no tuning on it): generate a clean calibration set for the two-node box (seeds 9301 to 9310), fit the single-node twin to it with the existing routine (report the fit quality, residual spread and consistency checks; this is a deliberate model mismatch), then run the final block on the two-node box: false tamper verdicts on clean/physical families, detection of the five lie families and drift, twin_out_of_date counts, bound validity, and the difference between payload potency (truth) and air-reported potency. Report honestly whatever happens; do NOT retune anything to improve the two-node numbers. This is the "twin tested against a box that does not follow its equations" result.

STEP 4: TIGHTER AND SAFER BOUND, WITH AN INTERVAL
